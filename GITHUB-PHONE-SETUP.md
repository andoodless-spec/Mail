# Обновить уже работающий «Тихий ящик» с телефона — v27

Эта инструкция — для **вашего уже заполненного GitHub-репозитория**, который подключён к **текущему работающему Vercel-проекту**. Она не создаёт ни другой репозиторий, ни другой Vercel-проект, ни пустую базу.

Архив `quiet-mailbox-vercel-v27.zip` содержит полный исходный код обновления. После распаковки GitHub Actions сделает обычный commit с обновлёнными файлами; подключённый Vercel увидит именно этот commit и сам начнёт deployment.

> **Ничего не делайте с `DATABASE_URL`.** Не удаляйте, не заменяйте, не копируйте её в GitHub и не создавайте новую базу. Та же Production-переменная текущего Vercel-проекта сохраняет все ящики, записи, настройки, карточки и рекорды.

## Один раз: добавьте универсальную кнопку распаковки в GitHub

Этот шаг нужен только сейчас. Следующие обновления будут состоять из загрузки ZIP и запуска этой же кнопки.

1. В Safari откройте **тот же GitHub-репозиторий**. Если кнопки неудобны, включите `aA → Запросить настольный веб‑сайт`.
2. Нажмите **Add file → Create new file**.
3. В поле имени вставьте ровно:

   ```text
   .github/workflows/unpack-update.yml
   ```

4. Откройте отдельный файл `github-phone-unpack-update.yml`, приложенный к этому релизу, и скопируйте **всё** его содержимое в большое поле редактора GitHub.
5. Нажмите **Commit changes** в текущую основную ветку репозитория.
6. Если GitHub спросит о правах на запись для Actions, откройте репозиторий → **Settings → Actions → General → Workflow permissions** → выберите **Read and write permissions** → **Save**.

После этого во вкладке **Actions** появится действие **«Опубликовать обновление Тихого ящика из ZIP»**. Старый `unpack-v26.yml` можно не удалять: для v27 используется новая универсальная кнопка.

## Опубликовать v27

1. В приложении «Файлы» оставьте файл с именем **`quiet-mailbox-vercel-v27.zip`** как есть. Не распаковывайте его на телефоне.
2. В этом же GitHub-репозитории нажмите **Add file → Upload files**.
3. Выберите ZIP из «Файлов» и нажмите **Commit changes** в ту же основную ветку.
   - На этом шаге в GitHub появится только файл ZIP — это нормально.
4. Откройте вкладку **Actions**.
5. Выберите **«Опубликовать обновление Тихого ящика из ZIP»** → **Run workflow**.
6. Оставьте выбранной текущую основную ветку. В поле **«Имя ZIP в корне этого репозитория»** должно быть ровно:

   ```text
   quiet-mailbox-vercel-v27.zip
   ```

7. Нажмите зелёную кнопку **Run workflow** и дождитесь зелёной галочки.

Действие распакует ZIP прямо в **тот же** репозиторий и создаст commit от `github-actions[bot]` с сообщением «Обновить Тихий ящик из ZIP».

## Что проверить в Vercel

1. Откройте Vercel → **тот же существующий проект** → **Deployments**.
2. После commit от `github-actions[bot]` дождитесь нового статуса **Ready**.
3. Откройте прежний адрес сайта. Зайдите в уже существующий ящик: записи и настройки должны быть на месте.

Не нажимайте **Add New → Project**, не открывайте `vercel.com/drop` и не меняйте переменные окружения. Подключение GitHub уже ведёт в правильный Vercel-проект.

## Если Actions завершилось ошибкой

- **`test: ... quiet-mailbox-vercel-v27.zip: No such file`** — ZIP не загружен в корень репозитория или в поле введено другое имя. Загрузите его через **Upload files** и повторите запуск с точным именем.
- **Permission denied / 403 при `git push`** — включите **Read and write permissions** в `Settings → Actions → General`, затем в Actions откройте запуск и нажмите **Re-run jobs**.
- **Зелёная галочка, но Vercel не начал deployment** — в Vercel откройте настройки текущего проекта → **Git** и убедитесь, что он всё ещё подключён к этому же репозиторию и ветке. Не создавайте новый Vercel-проект.

## Для следующего обновления

Универсальный workflow уже останется в GitHub. Нужно будет только загрузить новый ZIP в этот же репозиторий, открыть **Actions**, запустить это же действие и ввести имя нового ZIP. `DATABASE_URL` при этом по-прежнему не трогайте.
