# Заполнить подключённый GitHub-репозиторий v26 с телефона

Это инструкция для ситуации, когда текущий Vercel-проект уже подключён к **пустому** GitHub-репозиторию. Это нормально: Vercel не выгружает старые файлы в GitHub автоматически.

Архив `quiet-mailbox-vercel-v26.zip` — это полный исходный код сайта, а не только изменения. После этих шагов GitHub станет новым источником кода, а Vercel автоматически развернёт тот же проект с прежней `DATABASE_URL` и всеми ящиками.

## Сначала верните старый экран, если сайт сейчас пустой

В Vercel → ваш проект → **Deployments** найдите прежний зелёный deployment, который был до привязки пустого репозитория. В меню `…` выберите **Promote to Production**. Не выбирайте **Redeploy**: он снова соберёт пустой репозиторий.

## Шаг 1. Загрузите один ZIP в GitHub

1. В приложении «Файлы» оставьте архив с именем `quiet-mailbox-vercel-v26.zip` как есть, не распаковывая его.
2. В Safari откройте ваш новый GitHub-репозиторий и включите **aA → Запросить настольный веб‑сайт**.
3. Нажмите **Add file → Upload files**.
4. Выберите `quiet-mailbox-vercel-v26.zip` в «Файлах».
5. Внизу нажмите **Commit changes** в текущую основную ветку (обычно `main`).

Это временно загрузит только архив. Следующий шаг автоматически разложит его на все нужные файлы и папки.

## Шаг 2. Добавьте автоматическую распаковку

1. В репозитории нажмите **Add file → Create new file**.
2. В поле имени файла напишите строго:

```text
.github/workflows/unpack-v26.yml
```

GitHub сам создаст папки `.github` и `workflows`.

3. Откройте рядом файл `github-phone-unpack-v26.yml`, который вы получили вместе с инструкцией, и вставьте его содержимое в большое поле редактора GitHub.
4. Нажмите **Commit changes** в ветку `main`.

## Шаг 3. Дождитесь автоматического коммита

1. Откройте вкладку **Actions** в GitHub.
2. Запустится действие «Распаковать Тихий ящик v26».
3. Дождитесь зелёной галочки. Оно создаст второй commit «Добавить исходники Тихого ящика v26».
4. Если GitHub покажет ошибку о разрешении на запись, откройте репозиторий → **Settings → Actions → General → Workflow permissions**, выберите **Read and write permissions**, сохраните, затем во вкладке Actions нажмите **Re-run jobs**.

После второго commit в корне GitHub-репозитория появятся `index.html`, `package.json`, `vercel.json`, `api`, `assets`, `endpoints`, `lib` и остальные файлы.

## Шаг 4. Дождитесь deployment в Vercel

1. Откройте Vercel → этот же проект → **Deployments**.
2. После commit от `github-actions[bot]` Vercel должен начать новый deployment.
3. Дождитесь **Ready** и откройте прежний сайт.

Не меняйте `DATABASE_URL`. Поскольку это тот же Vercel-проект, новая версия подключится к прежней базе и увидит существующие ящики, записи, карточки и игровые рекорды.

## Если Vercel не начал deployment сам

В Vercel → **Deployments** найдите кнопку **Create Deployment** и выберите последний commit основной ветки — «Добавить исходники Тихого ящика v26». Не создавайте новый Vercel-проект.
