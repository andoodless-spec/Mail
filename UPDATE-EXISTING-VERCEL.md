# Обновить текущий «Тихий ящик» до v27 — без нового проекта

Эта инструкция рассчитана на уже работающий сайт. **Не создавайте новый Vercel-проект, новый GitHub-репозиторий или новую базу.**

## Вариант A — проект есть только в Vercel, без GitHub

Это ваш сценарий. GitHub не нужен: Vercel CLI может отправить новую версию прямо в уже существующий проект.

### 1. Сохраните точку отката

В [Vercel Dashboard](https://vercel.com/dashboard) откройте ваш существующий проект → **Deployments** и запомните последний рабочий deployment. Если что-то пойдёт не так, его можно вернуть через **Promote to Production**.

### 2. Подготовьте компьютер

1. Установите Node.js LTS, если его ещё нет: [nodejs.org](https://nodejs.org/).
2. Распакуйте `quiet-mailbox-vercel-v27.zip` в отдельную папку.
3. Откройте терминал в этой распакованной папке: в ней должны быть `index.html`, `package.json`, `vercel.json`, `api/`, `endpoints/`, `lib/` и `assets/`.

### 3. Привяжите папку к существующему Vercel-проекту

Выполните по очереди:

```bash
npx vercel@latest login
npx vercel@latest link
```

Во время `link` обязательно выберите:

- свой текущий аккаунт / команду Vercel;
- **Link to existing project? → Yes**;
- название **уже существующего** проекта «Тихого ящика».

Не выбирайте создание нового проекта. Команда создаст только локальную техническую папку `.vercel`; её не нужно загружать куда-либо.

### 4. Опубликуйте v27 в тот же проект

```bash
npx vercel@latest --prod
```

Команда загрузит содержимое папки в выбранный существующий проект и создаст Production deployment. Она не удаляет настройки этого проекта и не меняет его домен.

### 5. Ничего не меняйте в базе

В Vercel откройте текущий проект → **Settings → Environment Variables**.

- Убедитесь, что в **Production** по-прежнему есть `DATABASE_URL`.
- **Не удаляйте**, **не редактируйте** и **не создавайте новую** `DATABASE_URL`.
- Не переносите значение переменной в архив, GitHub или чат.

Именно прежняя `DATABASE_URL` содержит все текущие ящики и их данные. Новая версия подключится к ней автоматически и безопасно добавит только недостающие поля/таблицы.

### 6. Проверьте deployment и данные

1. После команды `npx vercel@latest --prod` откройте **Deployments** в том же Vercel-проекте. Новый deployment должен появиться автоматически.
2. Дождитесь статуса **Ready** и откройте прежний адрес сайта — не тестовый Preview URL.
3. Войдите в уже существующий ящик знакомым именем и PIN.
4. Проверьте, что видны старые записи, капсулы и карточки; затем откройте игры и карточку партнёра.

При обновлении того же проекта остаются тот же домен, та же база и текущие cookie-сессии. Данные не должны исчезнуть.

## Вариант B — обновление с iPad без GitHub и терминала

Этот вариант удобнее именно на **iPad**. Vercel поддерживает загрузку папки прямо в уже существующий проект без Git и CLI.

1. Скачайте `quiet-mailbox-vercel-v27.zip` в приложение **Файлы**.
2. Нажмите и удерживайте архив → **Распаковать**. Должна получиться папка, внутри которой сразу лежат `index.html`, `package.json`, `vercel.json`, `api`, `assets`, `endpoints` и `lib`.
3. Откройте Safari → [Vercel Dashboard](https://vercel.com/dashboard) → выберите **уже существующий** проект. Не открывайте `vercel.com/drop` и не нажимайте **Add New Project**: эти действия создают новый проект.
4. Откройте приложение **Файлы** рядом с Safari в Split View: проведите от нижнего края экрана вверх, вызовите Dock, удерживайте «Файлы» и перетащите его к краю экрана.
5. В «Файлах» зажмите пальцем **всю распакованную папку** и перетащите её на открытую страницу существующего Vercel-проекта. Если появится область «Drop files» / «Upload», отпустите папку туда.
6. В появившемся окне проверьте, что написано имя **вашего текущего проекта**, а не предложение создать новый. Подтвердите **Deploy**.
7. Дождитесь статуса **Ready** в разделе Deployments и откройте прежний адрес сайта.

При загрузке папки именно на страницу уже существующего проекта Vercel создаёт новый production deployment этого проекта. Его прежние Production-переменные, включая `DATABASE_URL`, остаются в проекте — не меняйте их.

### Если у вас только iPhone

На iPhone перетаскивание папки в Safari часто неудобно или недоступно. Сначала откройте сайт в Safari и включите **aA → Запросить настольный веб‑сайт**. Если в текущем проекте появится кнопка **Upload / Browse / Drop files**, выберите распакованную папку через «Файлы».

Если такой кнопки нет, не загружайте ZIP на `vercel.com/drop`: он создаст отдельный новый проект. Самый надёжный мобильный вариант — iPad в Split View либо любой компьютер на несколько минут.

## Если что-то не так

Не создавайте новую базу. В Vercel → **Deployments** выберите прежний успешный deployment и используйте **Promote to Production**. Это вернёт старый код, не затрагивая данные в PostgreSQL.
