# Как открыть «Тихий ящик» для других людей

Этот документ объясняет, как сделать сайт доступным по обычной ссылке, например `https://my-quiet-mailbox.vercel.app`, и сохранить общие данные пары в базе данных.

> **Важно:** публичный адрес сайта не делает записи публичными. Каждый новый человек может создать свой ящик, а к уже созданному ящику партнёр подключается только по коду пары и своему PIN.

---

## 1. Что понадобится

1. Архив `quiet-mailbox-vercel-v27.zip`.
2. Учётная запись **GitHub** — рекомендуется для загрузки и последующих обновлений.
3. Учётная запись **Vercel** — для хостинга сайта.
4. Облачная база PostgreSQL. Удобный вариант — **Neon**, но подойдёт любой совместимый PostgreSQL-провайдер.

Vercel публикует интерфейс и API, а PostgreSQL хранит пользователей, записи, игры и рекорды. Без базы сайт может выглядеть рабочим только в одном браузере, но не будет надёжно синхронизировать данные между людьми и устройствами.

---

## 2. Подготовьте проект из архива

1. Скачайте `quiet-mailbox-vercel-v27.zip`.
2. Распакуйте архив в отдельную папку.
3. Проверьте, что в **корне папки** лежат:
   - `index.html`;
   - `package.json`;
   - `vercel.json`;
   - папки `api`, `endpoints`, `lib`, `assets`.

Не загружайте в GitHub или Vercel папку `node_modules`: она не нужна и создаётся автоматически.

---

## 2.1. Обновите существующий сайт без потери ящиков — ваш сценарий

Если «Тихий ящик» уже опубликован, обновляйте **тот же GitHub-репозиторий и тот же Vercel-проект**. Не создавайте новый проект в Vercel и не делайте новую базу.

1. Откройте текущий Vercel-проект → **Settings → Git** и посмотрите, какой GitHub-репозиторий и ветка подключены.
2. В этом же репозитории замените файлы содержимым распакованного архива версии 26, затем сделайте commit и push в подключённую ветку.
3. В текущем Vercel-проекте → **Settings → Environment Variables** только проверьте наличие `DATABASE_URL` для **Production**. Не удаляйте, не переписывайте и не создавайте новое значение.
4. Дождитесь автоматического deployment в **Deployments** и откройте прежний адрес сайта.

### Если GitHub-репозитория нет

Можно обновить этот же проект прямо через Vercel CLI. В распакованной папке выполните:

```bash
npx vercel@latest login
npx vercel@latest link
npx vercel@latest --prod
```

Во время `link` выберите текущий аккаунт, **Link to existing project → Yes** и существующий проект. Не выбирайте создание нового проекта. Для этого способа нужен установленный Node.js LTS, но GitHub не нужен.

С прежней `DATABASE_URL` новая версия автоматически читает все старые пары, имена, PIN-хэши, записи, капсулы, договорённости, идеи, карточки партнёра, настройки и игровые рекорды. Схема обновляется добавочно и не удаляет записи. При обновлении того же проекта сохраняются и адрес, и cookie-сессии.

> Не копируйте `DATABASE_URL` в GitHub или в сам архив. Она должна оставаться только в защищённом поле Environment Variables текущего Vercel-проекта.

## 3. Загрузите код в GitHub — только для первого запуска

> Для обновления уже работающего сайта пропустите этот раздел и используйте шаги 2.1.

### Вариант A — без терминала

1. Откройте [github.com](https://github.com) и создайте новый репозиторий, например `quiet-mailbox`.
2. Не добавляйте готовый README или `.gitignore`, если GitHub предлагает это на первом экране.
3. В репозитории нажмите **Add file → Upload files**.
4. Перетащите **содержимое распакованной папки**, а не саму папку-обёртку.
5. Нажмите **Commit changes**.

### Вариант B — через терминал

В открытой распакованной папке выполните команды, заменив адрес репозитория на свой:

```bash
git init
git add .
git commit -m "Deploy quiet mailbox"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/quiet-mailbox.git
git push -u origin main
```

## 4. Создайте базу PostgreSQL — только для первого запуска

> Для обновления уже работающего сайта не создавайте новую базу: используется прежняя `DATABASE_URL`.

Ниже пример для Neon; действия у других PostgreSQL-провайдеров аналогичны.

1. Создайте новый проект PostgreSQL в панели Neon.
2. Откройте раздел **Connect** и скопируйте строку подключения. Она выглядит примерно так:

```text
postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require
```

3. Сохраните её в безопасном месте. Это **секрет**: не вставляйте строку в HTML, JavaScript, GitHub-репозиторий, чат с посторонними людьми или публичную инструкцию.

Ничего вручную создавать в базе не нужно: при первом запросе сайт сам создаст нужные таблицы.

---

## 5. Разверните сайт на Vercel — только для первого запуска

> Для обновления уже работающего сайта не нажимайте **Add New → Project**: Vercel развернёт commit автоматически в текущем проекте.

1. Откройте [vercel.com](https://vercel.com) и войдите через GitHub.
2. Нажмите **Add New → Project**.
3. Выберите GitHub-репозиторий `quiet-mailbox` и нажмите **Import**.
4. На экране настройки проверьте:
   - **Root Directory** — папка, где находятся `package.json` и `vercel.json`;
   - **Framework Preset** — можно оставить автоопределение или выбрать `Other`;
   - **Build Command** — не требуется;
   - **Output Directory** — не требуется.
5. Пока не нажимайте Deploy или откройте блок **Environment Variables**.

### Добавьте переменную базы

Создайте переменную:

| Name | Value |
| --- | --- |
| `DATABASE_URL` | строка подключения PostgreSQL из шага 4 |

Для удобства включите её для **Production**, **Preview** и **Development**. Также приложение поддерживает имена `POSTGRES_URL` и `NEON_DATABASE_URL`, но лучше использовать `DATABASE_URL`.

6. Нажмите **Deploy**.
7. После завершения Vercel покажет публичный адрес, например:

```text
https://quiet-mailbox-ваш-логин.vercel.app
```

Это и есть ссылка, которую можно отправлять другим людям.

---

## 6. Проверьте, что сайт действительно общий

Проверка важна: она отличает работу с общей базой от локального режима одного браузера.

1. Откройте публичную ссылку в обычном окне браузера.
2. Создайте ящик, укажите имя и PIN.
3. Скопируйте код пары.
4. Откройте ту же ссылку в режиме инкогнито, в другом браузере или на другом телефоне.
5. Нажмите «Подключиться», введите второе имя, свой PIN и код пары.
6. Создайте запись или сыграйте раунд. Убедитесь, что изменения отображаются с обоих устройств.

Для партнёра отправляйте **ссылку сайта и код пары**. Не отправляйте свой PIN и не передавайте строку `DATABASE_URL`.

---

## 7. Подключите свой домен (необязательно)

Если нужен красивый адрес, например `our-space.ru`:

1. Купите домен у регистратора.
2. В Vercel откройте проект → **Settings → Domains**.
3. Добавьте домен.
4. Vercel покажет, какие DNS-записи нужно создать у регистратора домена.
5. Скопируйте записи точно в том виде, в котором их показывает Vercel.
6. Подождите обновления DNS. Обычно Vercel сам выпустит HTTPS-сертификат.

После этого используйте новый домен вместо адреса `vercel.app`.

## 8. Как обновлять сайт позже

### При использовании GitHub

1. Измените файлы на компьютере.
2. Сделайте commit и push в ветку `main`:

```bash
git add .
git commit -m "Обновление Тихого ящика до v27"
git push
```

3. Vercel автоматически создаст новый Production deployment.

Если новая версия не подошла, в Vercel откройте **Deployments**, выберите предыдущую удачную версию и используйте **Promote to Production** / rollback.

### При обновлении из нового архива

Распакуйте `quiet-mailbox-vercel-v27.zip`, замените содержимое **того же подключённого репозитория** (кроме секретов), затем сделайте commit и push в прежнюю production-ветку. Не создавайте новый Vercel-проект. Переменная `DATABASE_URL` остаётся в настройках текущего проекта и не должна попадать в архив.

## 9. Безопасность и приватность

- Публична только страница входа; содержимое конкретного ящика не должно передаваться без кода пары и PIN.
- PIN короткий, поэтому не используйте сайт для банковских данных, документов, паролей или другой критически чувствительной информации.
- Никогда не публикуйте `DATABASE_URL`. Она должна существовать только в настройках Vercel и у владельца базы.
- Включите двухфакторную аутентификацию в GitHub, Vercel и у провайдера базы данных.
- Если делаете сайт для большого числа людей, создайте отдельный проект базы и следите за лимитами выбранного тарифа.

---

## 10. Частые проблемы

### «Не удалось создать ящик. Проверь подключение базы»

Проверьте, что `DATABASE_URL` добавлена в Vercel без лишних пробелов и включена для Production. Затем откройте **Deployments → Redeploy**.

### На разных устройствах не видно общих данных

Чаще всего переменная базы не настроена или открыт локальный файл вместо публичной Vercel-ссылки. Откройте адрес `https://...vercel.app` и проверьте шаг 6.

### На Vercel старая версия

Убедитесь, что изменения отправлены в нужный GitHub-репозиторий и ветку. В Vercel посмотрите последний deployment и при необходимости нажмите Redeploy.

### Домен не открывается

Проверьте DNS-записи в панели регистратора. Изменения DNS иногда распространяются несколько часов.
