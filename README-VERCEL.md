# Тихий ящик — обновление текущего сайта на Vercel

## Главное: обновляем существующий проект, не создаём новый

Этот архив предназначен для **обновления уже работающего Vercel-проекта**. Не создавайте новый проект и не создавайте новую базу данных.

Новый код сразу подтянет уже созданные ящики, пары, PIN-хэши, записи, капсулы, договорённости, настройки, карточки партнёра, результаты игр и рекорды, если в текущем проекте остаётся его прежняя переменная **`DATABASE_URL`**.

Приложение не очищает базу: схема использует только добавочные `CREATE TABLE IF NOT EXISTS` / `ALTER ... ADD ... IF NOT EXISTS` действия. В этой версии цветовой акцент памяти хранится в существующем JSON-поле карточки, поэтому отдельная миграция или перенос данных не нужны.

> Не удаляйте, не заменяйте и не публикуйте значение `DATABASE_URL`. Если оно уже задано в текущем Vercel-проекте, оставьте его как есть.

## Быстрое обновление текущего Vercel-проекта

1. Скачайте и распакуйте `quiet-mailbox-vercel-v28.zip` в отдельную папку.
2. Если проект подключён к GitHub, замените файлы в **том же** репозитории и сделайте commit/push в прежнюю production-ветку.
3. Если GitHub нет, откройте терминал в распакованной папке и выполните:

   ```bash
   npx vercel@latest login
   npx vercel@latest link
   npx vercel@latest --prod
   ```

   В ответах `link` выберите **Link to existing project → Yes** и укажите свой уже существующий Vercel-проект. Не выбирайте создание нового проекта.
4. В Vercel откройте текущий проект → **Settings → Environment Variables** и только проверьте, что прежняя `DATABASE_URL` осталась включённой для **Production**. Не меняйте её на новую строку.
5. После успешного deployment откройте обычный адрес сайта и убедитесь, что видны прежние ящики. Нынешний домен и сессии сохраняются, потому что обновляется тот же проект.

`vercel.json` и серверная функция уже включены. Команда сборки не нужна.

Пошаговая инструкция именно для текущего проекта — включая вариант **без GitHub и терминала с iPad**: [`UPDATE-EXISTING-VERCEL.md`](./UPDATE-EXISTING-VERCEL.md). Для уже работающего подключённого GitHub-репозитория используйте телефонный ZIP-workflow: [`GITHUB-PHONE-SETUP.md`](./GITHUB-PHONE-SETUP.md). Полная инструкция с проверками: [`PUBLISH-ON-VERCEL.md`](./PUBLISH-ON-VERCEL.md).

## Что добавлено в версии 28

- Вложенные поля, сворачиваемые строки, вторичные кнопки и списки больше не получают отдельные светлые квадраты: они используют ту же насыщенную поверхность, что и их родительская тематическая карточка.
- Это проверено для белой, розовой, фиолетовой, голубой, жёлтой и бирюзовой тем.
- В «Любимом селе» больше нет времени и слов в HUD: первая pill — только бегущее число текущего забега; вторая — `мой рекорд : рекорд партнёра` только цифрами, например `42 : 81`.
- Добавлен v28-совместимый workflow для уже существующего файла `.github/workflows/Cunpack-update.yml`.
- Сохраняются предыдущие улучшения: личная карточка с акцентами, пиксельная коровка и спокойная земля, native/CSS fullscreen fallback, обычные крестики-нолики с ничьими, приватные owner-relative карточки и мобильные исправления.

## Проверки

Перед упаковкой выполняются:

```bash
node --check app.js
node --check endpoints/partner-profile.js
node --check endpoints/games.js
node --check lib/games.js
python3 tests/static.py
node tests/fallback.mjs
node tests/browser-v19.mjs
```

Браузерная проверка запускается на 1280 и 390 px: она проверяет отсутствие отдельных светлых вложенных плиток во всех шести темах, числовые runner-pill без времени и слов, fullscreen и обычные победы/ничьи в крестиках-ноликах.
